**Claude:**

I couldn't find a new experiment: nothing's been pushed or posted since our last changes. If you've just run something on Colab, paste the output and I'll go through it.

Here's what your Phase 1 runs have shown so far. All of it is preliminary: it comes from a trial collection on one A100, before code review.

**1. Routing depends slightly on which prompts share a batch.**
You ran the same 400 prompts in five different random orders.
- **Overall:** 98% of top-4 expert choices were identical, and about 2% changed.
- **By depth:** changes grew from under 1% at the first layer to about 4.5% in the deepest layers. Once a token's experts change, the change carries into every later layer.
- **The control:** when the batch itself didn't change, routing was 100% bitwise identical. So the GPU isn't random; batch composition is what matters.

**2. The `position_ids` fix helped only a little.** It removed about 40% of the changes at the first layer, but only about 9% overall. Most of the rest comes from how GPU arithmetic depends on the shape of each batch.

**3. The changes happen at near-ties, and many at exact ties.** A changed decision's gap between the 4th and 5th expert is about 30 times smaller than a typical decision's. A quarter of changed decisions are exact ties. The smallest changes are whole steps of fp16 rounding.

**4. Batch noise is too small to decide how many experts to predict.** With batch noise as the only error, recall is already 99.5% with no extra experts. The buffer size will come from predictor error, which hasn't been measured yet.

**5. The buffer doesn't follow k + 2 or 1.5k.** In the analysis of different cut-offs, the buffer grows roughly with √k and then levels off. Only k = 4 is real routing, though, so this describes how crowded the ranking is, not what another model would do.

**6. The pipeline is fast.** A full collection takes about 6 minutes, down from an estimated 37.

Full write-ups are in [#114](https://github.com/scerruti/moe-expert-prefetching/discussions/114) and on `experiment/k-scaling`.
