The first #59 issue is Waleed's **P1**: **collection can lose rows and still report it passed.**

**What happens:** in `full_pipeline.py`, the code that builds a batch's Parquet rows drops any row with a NaN or infinite probability and logs a warning, nothing more. Everything downstream only sees the rows that are left:
- the row count the validator compares against;
- `validation_passed`, which stays `True`;
- the error list, which stays empty.

Waleed proved it by injecting 4 bad rows: 20 of 24 rows were saved, and the run reported success.

**Why it matters:** it's the same failure pattern as the swallowed hook errors in #111. Data can go missing silently, and a research dataset with gaps nobody knows about is worse than a run that stops. It hasn't happened in our real runs, but nothing would tell us if it did.

**The fix:**
1. **Write the test first:** inject bad routing values into a batch, and check that the collection fails rather than passing with fewer rows.
2. **Fail loudly:** when any row would be dropped, stop the run, or at least mark validation failed and record an error.
3. **Check completeness against what should exist:** every real token of every prompt, at all 24 layers, not just the rows that survived. That catches missing rows from any cause, not only NaNs.

**One decision for you on step 2: stop the run, or mark it failed and keep going?**
- **Stopping** is simplest and matches how we handled the hooks. It also makes Colab time used before the problem count for nothing.

> OK, invalid lines are being silently dropped and this causes later mismatches that aren't caught because the lines don't exist?

**Claude:**

Nearly. The rows are dropped silently, but there's no later mismatch at all, and that's the problem. Every later check counts only the surviving rows, so they all agree with each other:

1. A batch should produce, say, 24 rows: every real token of every prompt, × 24 layers.
2. Four rows contain NaN, so 20 are kept. The only sign is a warning in the log.
3. The expected count is built by adding up the rows that were *kept*: 20.
4. The Parquet check reads 20 rows from the file and compares them with the expected 20. They match.
5. `validation_passed` stays `True`.

Nothing ever compares against **what should exist**, which is 24. The expected number comes from the same reduced data, so the check can't fail. That's why the fix has two parts:
- **Don't drop rows quietly:** fail the run when any row is bad.
- **Count what should exist:** compute the expected rows independently, from the prompts' token counts × 24 layers. That catches missing rows from any cause, not only NaNs.
